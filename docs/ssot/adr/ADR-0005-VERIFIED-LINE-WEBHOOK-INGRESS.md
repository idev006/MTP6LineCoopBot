# ADR-0005 — Verified LINE Webhook Ingress

Status: ACCEPTED  
Date: 2026-09-09  
Decision owner: Project Architecture / Security  
Related: SEC-WEBHOOK-001, ADR-0003, RELEASE_GATES

## Context

LINE Messaging API webhook authenticity is established by verifying the `x-line-signature` request header against the exact raw request body using HMAC-SHA256 and the Messaging API channel secret.

The current Apps Script Web App receives `doPost(e)` with query/body event fields but cannot obtain the LINE signature header through the documented Web App event contract. The existing `webhook_secret` query parameter is a downstream shared-secret control; it is not proof that the original request came from LINE.

Direct production delivery from LINE to Apps Script therefore cannot satisfy the required signature-verification boundary.

## Decision

Introduce a small, provider-neutral **Verified Webhook Ingress Gateway** in front of Apps Script.

```mermaid
sequenceDiagram
    participant LINE as LINE Platform
    participant GW as Verified Ingress Gateway
    participant GAS as Apps Script Webhook
    participant EH as EventHandler

    LINE->>GW: POST raw body + x-line-signature
    GW->>GW: HMAC-SHA256 exact raw bytes
    alt signature invalid/missing
        GW-->>LINE: reject; no forwarding
    else signature valid
        GW->>GAS: POST exact raw body + downstream secret
        GAS->>GAS: verify downstream secret
        GAS->>EH: parse/process verified event
        GAS-->>GW: response
        GW-->>LINE: response
    end
```

## Trust Boundaries

### Public trust boundary
Only the gateway is configured as the LINE Developers webhook URL.

The gateway:
- receives the exact raw request body
- reads `x-line-signature` case-insensitively
- verifies HMAC-SHA256 before parsing JSON
- rejects missing/invalid signatures
- never logs channel secret, signature secrets, or raw webhook body

### Downstream boundary
Apps Script remains reachable as an HTTPS endpoint but processes webhook events only when the gateway's high-entropy downstream shared secret is valid.

The downstream secret is:
- independent from the LINE channel secret
- stored as deployment secret / Script Property
- never committed
- never logged
- rotated during gateway cutover or compromise response

## Provider Independence

The ingress implementation is a Node 24 HTTP service using standard HTTP/crypto APIs and no provider-specific business logic.

It must be deployable on a managed HTTPS/container platform such as Cloud Run or an equivalent provider. Hosting/provider choice is an Infrastructure Adapter decision and may change without altering the verification contract.

## Raw Body Rule

Signature verification MUST use the exact received UTF-8 bytes before:
- JSON.parse
- string normalization
- whitespace changes
- escaping/unescaping
- reserialization

Only after signature verification may the body be parsed or forwarded.

## Comparison Rule

Compare decoded signatures with a constant-time equality operation. Length mismatch rejects immediately without comparing secret-dependent content.

## Logging Rule

Allowed:
- request correlation ID generated by gateway
- verification outcome
- HTTP status
- event count only after verification
- latency
- downstream status

Forbidden:
- raw webhook body
- channel secret
- downstream shared secret
- full user/message payloads by default

## Failure Rule

Fail closed:
- missing signature → reject
- malformed signature → reject
- signature mismatch → reject
- missing channel secret → service unavailable
- missing downstream config → service unavailable
- downstream timeout/error → gateway error; never treat as successful processing

## Apps Script Change

Apps Script must remove raw body logging. Its existing downstream-secret check remains until deployment migration replaces/renames it through a controlled configuration change.

## Testing

Required:
- official LINE signature example/vector
- valid signature
- missing signature
- malformed Base64
- tampered body
- wrong secret
- case-insensitive header name
- forwarding only after successful verification
- downstream error/timeout behavior
- no raw body logging regression

## Release Gate

Code/CI completion is not production verification.

Before production:
1. deploy gateway to staging
2. configure channel secret and downstream secret
3. verify LINE Console webhook against gateway
4. confirm invalid signatures cannot reach Apps Script
5. confirm valid empty verification webhook returns success
6. update LINE Developers webhook URL to gateway production URL
7. monitor errors/redelivery
8. rotate old downstream secret if exposure is suspected

## Consequences

Positive:
- LINE-origin authenticity becomes cryptographically verified
- Apps Script limitation is isolated behind an adapter boundary
- gateway can evolve independently

Cost:
- one additional deployable component
- secret/config/deployment lifecycle required
- gateway availability becomes part of webhook availability

## Rejected Alternatives

### Keep webhook_secret only
Rejected: possession of URL/shared secret does not prove the request was signed by LINE.

### IP allowlist
Rejected: LINE does not publish fixed webhook source IP addresses.

### Parse JSON then verify
Rejected: modifying/deserializing body before verification can invalidate signature semantics.

### Put channel secret in Apps Script query
Rejected: leaks the wrong trust primitive and still cannot validate LINE's signature header.
